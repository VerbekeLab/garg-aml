# Golden fixtures — frozen GARG-AML behaviour

Generated by `scripts/make_golden.py` from the pre-extraction implementation, as
Phase 0 of the migration to the `garg-aml` package (see `PACKAGING_PLAN.md` §4).

**These files are the oracle. Never edit one to make a test pass.** A diff means
the code changed, not the fixture. Regenerating them is a separate commit with
its own justification.

## Layout

Four cases, each in its own directory:

| Case | Graph | Nodes | Note |
|---|---|---|---|
| `toy` | the paper's Figure A1–A6 example | 24 | node 23 pays 20/21/22, which all pay 19 — a textbook smurfing pattern |
| `synth_ba` | Barabási-Albert, n=200, m=2, 3 patterns | 245 | dense-ish, hub-structured |
| `synth_er` | Erdős-Rényi, n=200, p=0.001, 3 patterns | 90 | very sparse; most nodes have tiny neighbourhoods |
| `synth_ws` | Watts-Strogatz, n=200, k=2, p=0.01, 3 patterns | 245 | regular ring + rewiring |

Per case:

```
edges.csv                          the input: source,target
reduced_nodes_<dir>.csv            Louvain-reduced graph, node list
reduced_edges_<dir>.csv            Louvain-reduced graph, edge list
measures_<dir>_<variant>.csv       stage 1: block measures + block sizes
scores_<dir>_<variant>.csv         stage 2a: score, per score_type (column prefix)
features_<dir>_<variant>.csv       stage 2b: score + neighbourhood statistics
```

`<dir>` is `undirected` or `directed`; `<variant>` is `raw` (the graph as given)
or `reduced` (after Louvain at `resolution=10`, `seed=1997`).

## Design decisions

**The edge list is the input, not the generator.** Graphs are built once with
igraph and written immediately; every downstream number is computed from the
*reloaded* file. Tests therefore need only numpy/pandas/networkx/scipy — no
igraph, no seed, no generator.

**Reduced graphs are frozen as a node list *and* an edge list.** Louvain keeps
every node and drops only inter-community edges, so it leaves isolated nodes
behind — 18 of the toy graph's 24, for instance. Those are not incidental: an
isolated node is exactly what triggers the frozen D18/D20 edge cases. An edge
list alone cannot represent them.

**Louvain is frozen, not re-run, for downstream fixtures.** The reduced-variant
measures are computed from the frozen edge list. A networkx upgrade that changed
the partition would break one test (`reduce_graph`) instead of all of them.

**Node order is sorted out** of every frame, so the fixtures do not encode dict
insertion order.

**Features use `weighted_average` only** — the documented default and what every
experiment uses. The `basic` path is covered by the score fixtures.

## Regenerate / verify

```bash
python scripts/make_golden.py     # rewrite the fixtures (deliberate act)
python scripts/check_golden.py    # verify the current code still reproduces them
```

`check_golden.py` is the harness Phase 2 ports into the package as the L1 test.

## Verified environments

64 comparisons, all reproducing, on both ends of the supported range:

| | python | networkx | pandas | numpy | scipy |
|---|---|---|---|---|---|
| generated on | 3.11.0 | 2.8.8 | 1.5.3 | 1.24.4 | — |
| verified on | 3.11.0 | 3.6.1 | 3.0.6 | 2.4.6 | 1.x |

The Louvain partition is identical across those networkx versions, so the
fixtures are not environment-locked.

## Invariants confirmed at generation

- every score lies in [−1, 1] (0 violations across all 16 score files);
- node 23 of `toy`, the injected smurfing source, scores **exactly 1.0**;
- isolated nodes return 0 for all eight neighbour statistics (**D18**) and a
  score of −1 (**D20**);
- the directed score differs from its transpose-max in 205 of 245 nodes on
  `synth_ba`, so the max step is not a no-op (see `PACKAGING_PLAN.md` §3, D23).
